# Туризм без границ

Современный сайт образовательного социального проекта по вовлечению молодёжи от 18 лет в инклюзивный туризм. Планируемый набор — 50 человек.

> Открываем мир, в котором путешествия доступны каждому.

## Возможности

- Светлый адаптивный интерфейс, разделы проекта, программа 16 часов теории и 2–4 дня практики, сообщество, маршруты, результаты, партнёры, контакты.
- Заявка 18+ с серверной валидацией, сохранением в SQLite, уникальным номером и фиксацией согласия.
- Вход, профиль, изменение пароля, восстановление доступа одноразовым резервным кодом. Письма не отправляются, email не подтверждается.
- Кабинет участника: программа, расписание, материалы, практика, прогресс посещения и документы.
- Админпанель: поиск/фильтрация заявок, статусы, группы, публикация и редактирование контента, посещаемость, статистика, партнёры, обращения, экспорт CSV/XLSX, удаление данных участника.
- Серверное разграничение прав, CSRF, хеширование паролей и резервных кодов, отзыв старых сеансов после смены/восстановления пароля, ограничение частоты запросов, CSP и другие защитные заголовки.
- Клавиатурная навигация, ARIA-вкладки, skip-link, alt, крупный текст, reduced motion. Нет чат-ботов, внешних шрифтов и трекеров.

## Технологии

Python 3.13 (production-конфигурация), Flask, Jinja2, SQLite, Flask-WTF, Werkzeug, openpyxl, Gunicorn. Интерфейс — обычные HTML/CSS/JavaScript.

**Node.js и npm не требуются.** `package.json`, `node_modules` и frontend-бандлер не используются. Для этого серверного приложения нет команды `npm run build` и статической папки `dist`: production-релиз — проверенные исходники, зафиксированные зависимости и WSGI-конфигурация.

**GitHub хранит код, но GitHub Pages не запускает Flask/SQLite.** Для работающих заявок и кабинетов нужен серверный хостинг с постоянным диском. [Инструкция публикации](docs/DEPLOYMENT.md).

## Быстрый локальный запуск

Требуется Python 3.11+; проверка релиза выполнена на 3.13. Gunicorn предназначен для Linux/macOS; на Windows используйте локальный Flask либо Linux-контейнер.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
python app.py
```

Откройте порт 3000 на своём компьютере. Это **локальный режим разработки**, не публичный production-сервер.

На Windows: `.venv\Scripts\Activate.ps1`, затем те же команды `pip` и `python`.

Без `SECRET_KEY` локально создаётся случайный закрытый файл `instance/session.key`. В production ключ обязателен и передаётся только через окружение.

## Первый администратор

При первом запуске на пустом диске создаётся технический аккаунт со **случайным паролем**, без общего стандартного пароля. Индивидуальные данные входа записываются в `admin-access.txt` внутри каталога `INSTANCE_DIR` (по умолчанию `instance`). Прочитайте файл приватно на сервере, войдите через `/login`, затем в «Мой профиль» измените email и пароль. После сохранения нового пароля удалите первоначальный файл доступа с сервера.

Резервный код участника показывается только после регистрации или успешного восстановления. Сохраняйте его в менеджере паролей. При утрате кода организатору нужна отдельная безопасная процедура проверки личности; отправка писем и автоматическое восстановление без кода не реализованы.

## Production

1. Скопируйте `.env.example` в закрытый `.env`, **не добавляйте его в Git**.
2. Сгенерируйте свой ключ: `python -c "import secrets; print(secrets.token_hex(32))"`. Результат сохраните только в секретах хостинга или `.env`.
3. Задайте `APP_ENV=production`, `COOKIE_SECURE=1`, постоянный каталог `INSTANCE_DIR`, `PORT` и при необходимости `WEB_CONCURRENCY`.
4. Если используете `.env` в POSIX shell, загрузите его перед стартом: `set -a; . ./.env; set +a`. Приложение и Gunicorn сами файл `.env` не читают.
5. Запускайте `gunicorn --config gunicorn.conf.py app:app` за HTTPS reverse proxy.

В production приложение отказывается запускаться без `SECRET_KEY` длиной не менее 32 символов. На HTTP с `COOKIE_SECURE=1` браузер не отправляет cookie, поэтому вход и формы проверяйте через HTTPS. Исключение `COOKIE_SECURE=0` допустимо только для изолированной локальной проверки.

SQLite подходит для небольшого набора проекта на **одном экземпляре приложения** с несколькими WSGI-workers и общим локальным диском. Нельзя размещать независимые копии приложения с отдельными SQLite-базами или использовать эфемерный диск. Планируйте миграцию БД отдельно при росте нагрузки.

Полная инструкция по Git, хостингу, Docker, данным и обновлению: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Административная работа

- Группа задаётся одинаковым названием у участников и у публикаций.
- Аудитория публикации: пусто — всем участникам; название группы — этой группе; номер заявки — одному участнику. Не используйте номера заявок как названия общих групп.
- Материалы и документы — действительные HTTPS-ссылки, не встроенные загрузки файлов. Разрешения внешнего хранилища настраиваются отдельно. Персональные документы нельзя публиковать в общей аудитории. Ограничение видимости ссылки не защищает сам внешний файл от передачи третьим лицам.
- Посещение отмечает администратор, прогресс рассчитывается по доступным занятиям и практике.
- Тип «Партнёр» добавляет согласованную карточку на главную.
- Контактная форма сохраняет обращения во вкладке «Сообщения», без email-уведомлений.

## Проверки

```bash
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
black --check app.py gunicorn.conf.py tests/*.py scripts/*.py
pip-audit -r requirements.lock
python -m playwright install --with-deps chromium
python tests/browser_check.py
python tests/check_accessibility.py
```

Все тесты создают временные базы и случайные тестовые пароли. Они не копируют рабочую базу, не требуют существующего администратора и не читают реальные заявки. Скриншоты и отчёты сохраняются в `tests/artifacts/`. Браузерные тесты запускают собственный временный HTTP-сервер; рабочий сайт им не нужен.

Проверены 11 серверных сценариев, реальные браузерные формы/переходы, локальные ссылки и ресурсы, обновление маршрутов/вкладок и ширины 320/390/768/1024/1440 px. Автоматическая axe-проверка не является сертификацией WCAG и не заменяет тестирование скринридером. Подробности: [docs/AUDIT.md](docs/AUDIT.md).

## Чистый ZIP

```bash
python scripts/package_release.py
```

Архив и SHA-256 появятся в `release/`. Упаковщик включает только явно разрешённые исходники и конфигурацию, проверяет CRC, безопасные пути и наличие обязательных файлов. Он не включает `.env`, базу, ключи, заявки, логи, виртуальные окружения, старые архивы и результаты тестов. Для публичной публикации используйте этот архив, а не ZIP всей рабочей папки.

## До приёма реальных персональных данных

Заполните реквизиты оператора в админпанели, согласуйте юридические тексты и сроки хранения, выберите надлежащее размещение БД/резервных копий, настройте HTTPS и ограничения на reverse proxy. Прокси должен сам ограничивать частоту запросов с учётом реальных IP: приложение не доверяет произвольным forwarded-заголовкам.

Согласуйте программу и выдачу документов с КИУ, проверьте маршруты и транспорт до выезда, публикуйте только подтверждённых партнёров. Иллюстрация на первом экране не является фотографией реальных участников; её маркировка сохранена. Использование материалов и наименований согласует владелец проекта. Лицензия на собственный код/контент проекта владельцем пока не выбрана; открытая лицензия автоматически не назначается. Сторонние лицензии: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
